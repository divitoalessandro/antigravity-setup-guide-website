v1.1 Apr 2026
v1.1 Apr 2026 Current

Setup pages re-aligned to the Vibe 101 procedure. The three project-type pages (hobby, solo, team) now share the same seven-step "Before Building" skeleton, scoped per audience.

Setup procedure rebuild
  • Replaced the 05 / Prompts section on hobby, solo, and team with a single canonical 05 / Setup Procedure that walks through the same seven steps in the same order. Why: the old pages each ordered the prompts differently, contradicting the Vibe 101 checklist. Cross-page consistency means a reader switching between hobby/solo/team sees one familiar skeleton.
  • Promoted the interrogation prompt to Step 01 with its own block, instead of burying it inside the doc-generation prompt. Why: interrogation is the foundation of Vibe 101 — it surfaces gaps in thinking before AI starts generating on a broken premise.
  • Re-ordered the procedure so canonical docs (Step 03) are generated before CLAUDE.md (Step 04), and CLAUDE.md now references those docs by name. Why: CLAUDE.md is meant to condense the rules from the docs — writing it first inverts the dependency.
  • Added a UI Screenshots step (Step 06) with a dedicated prompt to set up a /screenshots folder and reference checklist. Why: Step 06 of the Vibe 101 checklist was missing entirely from the setup pages. Without visual references, AI invents UI from scratch.
  • Dissolved the old Project Bootstrap megaprompts: git/README → Step 07, progress.txt → Step 05, lessons.md → Step 04, CI/lint/branch-protection → optional Step 07b. Why: a megaprompt that does seven things at once doesn't teach the procedure. Splitting it makes each step independently runnable and reviewable.
  • Introduced an explicit Step 07b — Project Tooling (solo & team only) for CI/CD, linting, branch protection, and conventions. Why: Vibe 101's "Before Building" intentionally stops at git init. Tooling is real but separate — flagging it as 07b keeps the canonical seven steps clean while preserving the team-grade content.
  • Scoped Step 03 per page: hobby generates only PRD.md; solo generates PRD + TECH_STACK + IMPLEMENTATION_PLAN; team generates the full six canonical docs. Why: same skeleton, right depth. A hobby project doesn't need BACKEND_STRUCTURE.md; a team build absolutely does.
  • Added a pointer at the top of Day 1 on every page linking down to the Setup Procedure. Why: readers who land on the workflow section first get steered to run the procedure before any product code is written.
Models refresh
  • Claude Opus 4.6 → Opus 4.7 (released Apr 16, 2026). Description updated to reflect the agentic-coding step-change and new high-resolution image support. Why: Opus 4.7 superseded 4.6 a week before this release; recommending the older version would steer users to a deprecated tier.
  • GPT-4o → GPT-5.5 (released Apr 23, 2026). Repositioned as a tool-using generalist rather than a "broad knowledge fallback." Why: GPT-4o is two generations behind. GPT-5.5 is materially better at agentic coding workflows, which is the relevant use case in an Antigravity context.
  • Added an efficient tier: Gemini 3.1 Flash (high-throughput, $0.25 / $1.50 per M tokens) and Claude Haiku 4.5 (fast agent runner, $1 / $5 per M tokens) with use-case guidance for each. Why: the original lineup only covered frontier models. Most real agentic work — sub-agents, classification loops, data extraction, in-IDE autocomplete — is wasted on Opus or 3.1 Pro. Showing the cheap-fast tier prevents users from defaulting to the expensive model for narrow tasks.
  • Gemini 3.1 Pro and Claude Sonnet 4.6 are still current as of Apr 2026 — no changes.
Site
  • Bumped homepage version badge from v1.0 / Mar 2026 to v1.1 / Apr 2026.
  • Added Changelog to navigation across all pages so future optimizations are discoverable in one place.
