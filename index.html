Essential Plugins (Tier 1)

These 5 plugins earn their place on day one. Everything else is optional until you have a concrete use case.

Plugin What it does Why essential
superpowers Core runtime for skills, git worktrees, brainstorming, debugging Everything else builds on this
episodic-memory Gives Claude persistent memory across sessions Without this, Claude forgets everything between conversations
context7 Pulls live library documentation into context Prevents hallucinated APIs and outdated suggestions
commit-commands Commit, push, and open PRs in a single step Daily time saver with minimal overhead
github GitHub integration for issues, PRs, and repo management Required if your code lives on GitHub
If you can't name a concrete use case from the last week, don't enable it.

When to Use Which Model

Antigravity supports multiple AI models. Each has a sweet spot.

Model Best for When to reach for it
Gemini 3.1 Pro Long context, codebase-wide reasoning, exploration Default model in Antigravity. Use for broad codebase questions and refactoring.
Claude Sonnet 4.6 Nuanced writing, complex logic, architecture decisions When you need careful reasoning, planning, or handling ambiguous requirements.
GPT-4o General-purpose, wide ecosystem knowledge When specifically requested by a client or team, or for broad general knowledge.

Workflow Habits

Agent-first development changes how you work. These habits make the difference.

  • Start every session with context. Use episodic-memory to recall previous decisions before diving in.
  • Plan before you code. Use brainstorming and writing-plans skills. Let the agent think through the approach first.
  • One task per agent. Keep subagents focused. Broad requests produce mediocre results.
  • Verify before marking done. Run tests, check output, read diffs. Never trust "it should work."
  • Commit frequently. Small, focused commits. Use conventional commit messages. Let the agent handle the boilerplate.
  • Review agent output like a PR. Read the code. Understand the changes. You're the architect, the agent is the implementer.
  • Document decisions, not code. Write down why you chose an approach, not what the code does. The code speaks for itself.
