00 / Get Started Download Google Antigravity

Antigravity is Google's agent-first IDE — a VS Code fork with Gemini built in. Get it first, then connect Claude Code.

Download Antigravity →
1
Install the Claude Code extension
Open the Extensions panel in Antigravity (Cmd+Shift+X), search for Claude Code by Anthropic, and install it.
2
Sign in to your Anthropic account
You need a Claude Pro, Max, or Team subscription. Alternatively, connect via the Claude API with your API key if you prefer usage-based billing.
3
Verify the connection
Open the Claude Code panel and send a test message. If you see a response, you're connected. Install the superpowers plugin next — it's the foundation for everything below.

01 / Plugins Essential Plugins

Five plugins that earn their place on day one. Everything else is optional until you have a concrete reason.

superpowers
Core runtime for skills, git worktrees, brainstorming, debugging, and plan execution.
Everything else builds on this. It is the backbone.
episodic-memory
Gives Claude persistent memory across sessions. Recalls previous decisions, context, and patterns.
Without this, every session starts from zero. Non-negotiable.
context7
Pulls live, up-to-date library documentation directly into the conversation context.
Prevents hallucinated APIs and outdated code suggestions.
commit-commands
Commit, push, and open pull requests in a single command. Handles conventional commit messages.
Daily time saver. Minimal overhead, real daily value.
github
GitHub integration for issues, pull requests, repo management, and CI status checks.
Required if your code lives on GitHub.
If you can't name a concrete use case from the last week, don't enable it.

02 / Models When to Use Which Model

Antigravity supports multiple AI models. Each has a distinct strength. Pick deliberately, not randomly.

Gemini 3.1 Pro
The default workhorse. Massive context window.
Best for codebase-wide exploration, large refactors, and questions that require reasoning across many files simultaneously.
Start here for everyday tasks in Antigravity. Its long context window makes it ideal for "show me everything" type queries and broad refactoring across dozens of files.
Claude Opus 4.6
The heavyweight. Deep thinking, hard problems.
The most capable Claude model. Excels at complex multi-step reasoning, intricate debugging, and tasks where correctness is critical.
Reach for Opus when the problem is genuinely hard — deep architectural decisions, subtle bugs that Sonnet can't crack, or when you need the highest quality output regardless of speed. Costs more, worth it for the hard stuff.
Claude Sonnet 4.6
Fast, sharp, cost-efficient. The daily driver.
Excellent balance of speed and intelligence. Strong at architecture planning, code generation, nuanced writing, and trade-off analysis.
Your go-to Claude model for most tasks. Fast enough for iteration, smart enough for complex work. Use Sonnet first, escalate to Opus only when you hit a ceiling.
GPT-4o
General-purpose. Broad ecosystem knowledge.
Wide training data, strong general capability. Useful for broad knowledge questions and when teams standardize on OpenAI tooling.
Use when working with a team that requires OpenAI, or for tasks that benefit from its broad general knowledge base. Not your primary — a fallback for specific contexts.

03 / Workflow Habits for Agent-First Development

Working with AI agents changes how you operate. These habits separate productive sessions from wasted ones.

01
Start every session with context
Use episodic-memory to recall previous decisions before diving into new work.
02
Plan before you code
Use brainstorming and writing-plans skills. Let the agent think through the approach first.
03
One task per agent
Keep subagents focused on single responsibilities. Broad requests produce mediocre results.
04
Verify before marking done
Run tests, check output, read diffs. Never trust "it should work."
05
Commit frequently
Small, focused commits. Conventional messages. Let the agent handle the boilerplate.
06
Review output like a pull request
Read the code. Understand the changes. You are the architect, the agent is the implementer.
07
Document decisions, not code
Write down why you chose an approach. The code speaks for itself.
08
Use worktrees for isolation
Never experiment on main. Worktrees give you a clean sandbox without stashing.
