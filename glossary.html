01 / AI-Dev Basics
Context Window ▾

The context window is the "working memory" of an LLM — everything the model can simultaneously "see" and take into account: your prompt, previous messages, uploaded files, and code.

Vibe tip When a model starts "forgetting" earlier instructions, the context window is full. Fix: summarize key points at the start of each new session (system prompt or memo block).
Analogy Like a whiteboard in a meeting room: only what's written on it is visible to everyone. When it's full, you have to erase the old stuff.
Token ▾

Tokens are the smallest units an LLM breaks text into — roughly 4 characters or ¾ of an English word. AI APIs are billed per token consumed.

Vibe tip The more precise your prompt, the fewer tokens you waste. Short, clear instructions beat sprawling essays. Quality over quantity when prompting.
Analogy Like SMS character limits on old phone plans: you have a budget, use it wisely.
LLM Large Language Model ▾

An LLM is an AI model trained on massive amounts of text that can generate, understand, and transform language. Claude, GPT-4, Gemini — all LLMs.

Vibe tip Different LLMs have different strengths: Claude excels at reasoning and long context, GPT-4 has broad creativity. Pick the right model for the task.
Analogy Like different specialists: the architect plans the building, the contractor builds it — both experts, different strengths.
RAG Retrieval-Augmented Generation ▾

RAG is a technique where an LLM retrieves external knowledge sources (databases, documents) in real time before responding — keeping knowledge current and specific.

Vibe tip When building an AI feature that should reference your own data, say: "Implement this with RAG so the AI can reference our knowledge base." This is the key difference from a generic chatbot.
Analogy Instead of memorizing everything, you have an open book during the exam. You can look it up — the answer is current and accurate.
System Prompt ▾

A system prompt is the background instruction that gives an LLM its role, tone, and constraints — it runs invisibly before your actual conversation begins.

Vibe tip In your own AI apps, the system prompt is your most powerful tool. A good system prompt prevents 80% of hallucinations before they happen.
Analogy Like a job briefing before an interview: you tell the candidate who they should be before they enter the room.
Embedding / Vector ▾

Embeddings are numerical representations of text as multi-dimensional vectors — allowing a computer to "understand" that "dog" and "puppy" are semantically close.

Vibe tip When building AI-powered search or RAG, you need embeddings. Tell your AI: "Use embeddings to enable semantic search over this dataset."
Analogy Like a map of meaning: words with similar meanings are geographically close to each other.
Fine-Tuning ▾

Fine-tuning means continuing to train an existing LLM on a specific, custom dataset — turning a generalist model into an expert for your particular domain.

Vibe tip Fine-tuning is rarely the first step. Always start with prompt engineering. It saves time and money, and solves most problems before you need training.
Analogy Like a generalist doctor who becomes a specialist: the foundational knowledge stays, specific expertise is added on top.
Hallucination ▾

Hallucinations are confident errors from an LLM — it invents facts, functions, or code that sounds plausible but is simply wrong.

Vibe tip Always verify. Prompt tip: "If you're unsure about a fact or function name, say so explicitly instead of guessing." Let the AI cite sources or test the code directly.
Analogy Like a confident colleague who makes up an answer instead of saying "I don't know." Sounds convincing, but it's nonsense.
02 / Modern Workflow
MCP Model Context Protocol ▾

MCP is an open protocol that connects AI models to external tools and data sources — a universal socket between Claude and your code editor, database, or APIs.

Vibe tip MCP is a game-changer: you can connect Claude directly to Figma, GitHub, Notion, or your own services — no copy-paste between tools.
Analogy Like USB: every device used to need its own connector. MCP is the universal USB port for AI tools.
Agentic Workflow ▾

Agentic workflows are AI flows where the model plans and executes multiple steps autonomously — it researches, writes code, tests, corrects, and repeats until the goal is reached.

Vibe tip For complex features, give a high-level goal instead of step-by-step instructions: "Act as an autonomous agent. Your goal is [X]. Plan the steps, execute them, and report back when done."
Analogy Like a self-directed freelancer: you give the brief, they deliver the result — without micromanagement.
Iterative Prompting ▾

Iterative prompting is the process of refining a result through multiple focused follow-up prompts, rather than demanding everything in one massive prompt.

Vibe tip Strategy: 1) Generate rough structure. 2) Deepen one area. 3) Handle edge cases. 4) Run a code review prompt. Like sculpting, not casting.
Analogy Like film editing: you shoot raw footage, then cut, then refine. No film is finished after the first take.
Prompt Engineering ▾

Prompt engineering is the skill of crafting instructions for AI models so that output is precise, consistent, and high quality — one of the most valuable skills in vibe coding.

Techniques Few-Shot (examples in the prompt), Chain-of-Thought ("think step by step"), Role Assignment ("you are a senior React developer").
Analogy Like a precise recipe: the more specific the ingredients and steps, the more reproducible the result.
AI Code Review ▾

AI code review means having the AI systematically check generated or written code for bugs, security issues, and best practices — a structured quality gate before shipping.

Vibe tip Before deploying, prompt: "Review this code for: 1) Security vulnerabilities, 2) Performance issues, 3) Edge cases I might have missed, 4) SOLID principle violations."
Analogy Like spell-check, but for security and quality — not infallible, but much better than nothing.
Multi-Agent System ▾

A multi-agent system consists of multiple specialized AI agents working together: one plans, one writes code, one tests, one documents.

Vibe tip For larger projects: "You are the Architect agent. Your job is only to design the structure, not write code. Hand off to the Coder agent when done."
Analogy Like an operating room team: surgeon, anesthesiologist, assistant — each a specialist, together they deliver the result.
03 / Core Dev Concepts
API Application Programming Interface ▾

An API is a clearly defined communication channel between two pieces of software — it specifies what requests can be made and what format responses come back in.

Vibe tip Almost everything in modern apps runs through APIs. Prompt: "Create a wrapper function for this API that handles errors gracefully."
Analogy Like a power outlet: you know what goes in (plug) and what comes out (power) — what happens behind the wall is irrelevant.
Frontend vs. Backend ▾

Frontend is everything the user sees and interacts with (browser/app). Backend is the engine behind it: server, database, business logic — what the user never directly touches.

Vibe tip Always be explicit about which layer you mean: "This validation should happen on the backend, not just the frontend." Frontend-only validation is never secure.
Analogy A restaurant: frontend = dining room and waitstaff. Backend = kitchen and storage. The guest only sees the restaurant.
State Management ▾

State is your app's current condition — which user is logged in, what's in the cart, whether a modal is open. State management describes how that state is stored and shared.

Vibe tip One of the most common bugs: inconsistent state. Prompt: "Where should this state live — local component state or global store? Explain the tradeoffs."
Analogy Like a cash register system: the current balance (state) must be visible to all cashiers and always up to date.
Database Schema ▾

A database schema is the "blueprint" of your database: which tables exist, what fields each table has, and how tables relate to each other.

Vibe tip The schema is one of your most important design decisions — mistakes here are expensive. Prompt early: "Design a normalized database schema and explain the relationships."
Analogy Like the floor plan of a house: changes after construction are expensive and disruptive.
Refactoring ▾

Refactoring means improving existing code — making it more readable, efficient, or maintainable — without changing its external behavior.

Vibe tip Prompt regularly: "Refactor this code to be more readable and maintainable. Keep the same behavior." Good code today saves debugging hours tomorrow.
Analogy Like a home renovation: the house stays the same, but it's tidier, more pleasant, and more functional.
Pull Request PR ▾

A pull request is a proposal to merge code changes into the main codebase — coupled with a review process where teammates inspect and comment on the code.

Vibe tip Even solo, a PR workflow has value: "Write a PR description for these changes, including what was changed, why, and how to test it." Forces you to think it through.
Analogy Like editing before publishing: the text gets one more pass before it goes out.
Middleware ▾

Middleware is code that runs between a request and a response — it can check (auth?), transform (logging), or block (rate limiting) before the request reaches its destination.

Vibe tip Always build auth, logging, and rate limiting as middleware — never inline in routes: "Add authentication middleware to protect all routes under /api/private."
Analogy Like airport security: you arrive, you're checked, you enter — or you don't.
Dependencies ▾

Dependencies are external libraries or packages your project uses — stored in package.json (Node) or requirements.txt (Python). Without them, your code won't run.

Vibe tip Be careful with too many dependencies: "Do I really need a library for this, or can we implement it with native features?" Fewer dependencies = fewer security risks.
Analogy Like subcontractors: useful and efficient, but you depend on their reliability.
Async / Await ▾

Asynchronous code lets your app wait for slow operations (API calls, database queries) without blocking everything else. async/await is the modern, readable syntax for this.

Vibe tip If your app "hangs" or shows data too late: "Review this async code and make sure all asynchronous operations are properly awaited and errors are caught."
Analogy Like ordering coffee: you order (request), go sit down (next operation), the barista calls your name (response).
REST vs. GraphQL ▾

REST and GraphQL are two API designs: REST has fixed endpoints (/users, /orders), GraphQL has a single endpoint where the client specifies exactly what data it needs.

Vibe tip Simple apps: REST. Complex, data-heavy apps: GraphQL. Prompt: "For my use case [X], should I use REST or GraphQL? Explain the tradeoffs."
Analogy REST = fixed-price menu. GraphQL = buffet where you only take what you want.
04 / Deployment & Ops
Vercel ▾

Vercel is a cloud platform optimized for frontend frameworks (Next.js, React, Vue) — push to GitHub and your app is live in seconds. Zero-config deployment.

Vibe tip Ideal for vibe coders: Vercel handles hosting, SSL, CDN, and deployments automatically. Just push and ship.
Analogy Like an automatic transmission: you don't need to know how it works — it just works.
Environment Variables .env ▾

Environment variables are configuration values (API keys, database passwords) stored outside your code — in a .env file locally, in secrets at your hosting provider.

Vibe tip Never write API keys directly in code. The .env file never goes into git. Add it to .gitignore immediately.
Analogy Like a key safe: not everyone who sees the blueprint (code) should have the key (API key).
Git & GitHub ▾

Git is the version control system for code — every change is saved, you can rewind to any point. GitHub is the cloud platform that hosts Git repositories and enables team collaboration.

Vibe tip Commit early and often. The 5 essential commands: init, add, commit, push, pull.
Analogy Like a save slot in a video game: you can return to any previous state at any time.
CI/CD Continuous Integration / Delivery ▾

CI/CD is a pipeline that automatically runs tests, builds your code, and deploys it on every push — without any manual steps.

Vibe tip Even solo, CI/CD is worth setting up: "Create a GitHub Actions workflow that runs tests and deploys to Vercel on every push to main."
Analogy Like quality control on an assembly line: every product is checked before it ships.
Docker / Container ▾

Docker packages an app with all its dependencies into a container — a standardized "package" that runs identically on any system. "Works on my machine" becomes irrelevant.

Vibe tip For backends and complex services: "Create a Dockerfile for this Node application and explain each step."
Analogy Like shipping containers: wherever the container goes, the contents are always packed and protected the same way.
DNS & Domain ▾

DNS (Domain Name System) translates human-readable domain names (myapp.com) into IP addresses (185.x.x.x) that computers understand. It's the internet's phone book.

Vibe tip DNS changes can take up to 48 hours (TTL). When setting up a domain: "Walk me through connecting my domain to Vercel, including which DNS records to set."
Analogy Like a street address: you say "123 Main St" and the GPS finds the coordinates — DNS does the same for websites.
Logging & Monitoring ▾

Logging records what happens in your app (errors, user actions, performance). Monitoring gives you real-time alerts when something goes wrong.

Vibe tip You only realize how important logging is once production crashes: "Add structured logging to this API. Log errors with context and performance timing for database queries."
Analogy Like a flight recorder: when something goes wrong, you have the record of what happened.
05 / Vibe-Coding Slang A–Z
A Ablation Test ▾

You systematically remove individual parts of a system to understand what effect each has. For prompts: which part of the prompt produces which result?

Vibe tip When a prompt works well, gradually shorten it and see when quality drops. This finds your "Minimum Viable Instruction."
B Boilerplate ▾

Boilerplate is standardized, repetitive code that every project needs — setup, config, standard imports. AI is perfect for generating it.

Vibe tip Never write boilerplate manually: "Generate the boilerplate for a Next.js 14 project with TypeScript, Tailwind, shadcn/ui and Prisma ORM."
C Context Switching ▾

Context switching is the constant toggling between different tasks or tools — editor, browser, AI chat, terminal — which drains focus and momentum.

Vibe tip Minimize context switches. Use AI tools directly inside your editor (Cursor, Copilot, Antigravity). The less you app-switch, the more you stay in flow.
D Dead Code ▾

Dead code is code that exists in the project but is never executed — old features, commented-out functions, unused variables. It confuses AI and bloats the codebase.

Vibe tip Clean up regularly: "Analyze this codebase and identify dead code, unused imports and unreachable functions that can be safely removed."
E Edge Case ▾

An edge case is a rare but possible scenario outside the normal workflow — empty inputs, extremely large numbers, missing data. Often the source of bugs.

Vibe tip AI forgets edge cases. Always prompt explicitly: "What edge cases should I handle for this feature? List them and then implement handling for each."
F Feature Creep ▾

Feature creep is the uncontrolled growth of features outside the core scope — a common problem when AI keeps proposing ideas and you keep saying yes.

Vibe tip Define scope upfront: "For now, we're building ONLY these features: [X, Y, Z]. Reject any suggestions that go beyond this scope."
G Golden Path ▾

The golden path is the ideal, frictionless journey a typical user takes through your app — no errors, no detours, no confusion.

Vibe tip Build the golden path first, then handle edge cases: "Implement the golden path for [feature] first. We'll handle errors and edge cases in the next iteration."
H Hot Reload ▾

Hot Reload (or Hot Module Replacement) updates the app in the browser the moment you save code — without a manual refresh and without losing state.

Analogy Like a live preview while writing: you instantly see how the text looks as you format it.
I In-Context Learning ▾

In-context learning means giving the LLM examples directly in the prompt (Few-Shot) so it learns the pattern and applies it to new cases — without any training.

Vibe tip Massively underrated technique. Instead of explaining, show 2–3 examples: "Here are 3 examples of how I want the output: [...]. Now do the same for: [new case]."
J Jailbreak ▾

A jailbreak is an attempt to bypass the safety limits of an AI model. Ethically questionable to illegal — and mostly ineffective on well-built models.

Vibe tip Don't. There's almost always a legitimate way to reach the same goal. Better prompting beats boundary testing every time.
K Knowledge Cutoff ▾

The knowledge cutoff is the date up to which an LLM has training data — after that, it knows nothing about new events, libraries, or API changes.

Vibe tip Always specify the version: "I'm using Next.js 15.1 (released after your cutoff). Here's the relevant docs excerpt: [...]." Prevents hallucinations about outdated APIs.
L Latency ▾

Latency is the time between a request and a response — in AI apps, often the biggest UX problem. Streaming responses and thoughtful loading state design are the solution.

Vibe tip Always build loading states: "Add a skeleton loading state while the AI response is streaming. Use progressive rendering so users see partial results immediately."
M MVP Minimal Viable Product ▾

An MVP is the smallest version of a product that delivers real value — just enough to get feedback, without needing to build everything perfectly first.

Vibe tip Define your MVP rigorously and defend it against feature creep: "Help me define the absolute minimum features for an MVP of [idea]. What can we cut without losing core value?"
N Negative Prompting ▾

Negative prompting is the technique of explicitly telling AI what it should NOT do — often more effective than only describing what you want.

Vibe tip Combine positive and negative: "Write clean React. Do NOT use class components, do NOT use deprecated lifecycle methods, do NOT install additional libraries."
O Over-Engineering ▾

Over-engineering means building an overly complex solution for a simple problem — common with AI, because models love proposing full enterprise-grade architectures.

Vibe tip "Keep this simple. I don't need enterprise patterns. Build the simplest solution that works for my use case of [X users/requirements]."
P Pair Programming with AI ▾

Pair programming with AI means developing in dialogue with the model — you provide context and decisions, the AI writes and explains code, you discuss approaches together.

Vibe tip Be the senior engineer on the team: "Explain why you chose this approach over [alternative]. What are the tradeoffs?" Understanding beats fast output.
Q Query ▾

A query is a request to a database — written in SQL to read, write, update, or delete data. Poorly written queries are a common performance killer.

Vibe tip "Analyze this database query for performance issues. Are there missing indexes? Can we optimize the JOIN operations?"
R Rubber Ducking ▾

Rubber ducking means explaining your problem out loud — to a rubber duck, or to AI. Just the act of articulating the problem often reveals the solution.

Vibe tip "I'm going to explain my problem to you. Don't solve it yet — just ask me clarifying questions until we both fully understand what's happening."
S Scaffolding ▾

Scaffolding is the automatic generation of basic structures — folders, files, code templates — for a new project or feature.

Vibe tip "Scaffold a complete project structure for [type]. Include folder structure, config files, and placeholder components with comments."
T Technical Debt ▾

Technical debt is accumulated "bad code" — quick-and-dirty solutions that work short-term but become expensive to maintain long-term.

Vibe tip Review regularly: "Review this codebase and identify technical debt. Prioritize what should be refactored first and why."
Analogy Like credit card debt: convenient now, but the interest (bugs, maintenance cost) catches up with you.
U Unit Test / Smoke Test ▾

Unit tests verify individual functions automatically. A smoke test is a quick, surface-level check that the most important functions of an app basically work — not whether everything is perfect, just whether the app is "breathing."

Vibe tip AI is great at writing tests: "Write comprehensive unit tests for this function. Include edge cases, invalid inputs and boundary conditions."
Analogy Like the first sip of coffee in the morning: you're not checking if it's perfect — you're checking if the machine made coffee at all.
V Versioning SemVer ▾

Semantic Versioning (SemVer) is a numbering system for software releases: MAJOR.MINOR.PATCH — 2.4.1 means 2nd major version, 4th new feature, 1st bugfix.

Vibe tip When updating dependencies, a new MAJOR version may have breaking changes: "What are the breaking changes between [Library] v2 and v3? What do I need to update in my code?"
W Webhook ▾

A webhook is an automatic HTTP call that a service sends when an event occurs — instead of constantly polling ("did anything happen?"), you get notified automatically.

Vibe tip For integrations (Stripe, GitHub, Slack), always use webhooks: "Set up a webhook endpoint that listens for [event] from [service] and handles it securely with signature verification."
Analogy Like push notifications: you don't call to ask for news — they notify you when something happens.
X XSS Cross-Site Scripting ▾

XSS is a security vulnerability where attackers inject malicious JavaScript into your website — through user inputs that aren't properly escaped or sanitized.

Vibe tip A common blind spot in AI-generated code: "Review all user input handling in this code for XSS vulnerabilities. Are all outputs properly escaped?"
Y YAGNI ▾

YAGNI — You Aren't Gonna Need It — is a software principle: don't build what you might need someday. Only build what you need right now. Prevents over-engineering.

Vibe tip When AI suggests features that "could be useful": ask yourself if you actually need this now. Simpler code is more maintainable code.
Z Zero-Day Vulnerability ▾

A zero-day vulnerability is a security flaw with no patch yet available — "day zero" means the developer had zero days to fix it before it was discovered or exploited.

Vibe tip Keep dependencies updated and subscribe to security alerts for key libraries: "What security scanning tools should I set up to catch vulnerabilities in my dependencies automatically?"
06 / Best Practices

The 10 most important rules for professional vibe coding — so you debug less and build more.

# Rule Description
01 Context before code Always explain the bigger context first: "I'm building a [type] app for [audience] using [stack]. Now I need to…"
02 One thing at a time Never ask AI to build features A, B, and C simultaneously. Iterate: finish A, commit it, then move to B.
03 Name your stack explicitly Always specify: framework, version, key libraries. "Using React 18, Next.js 15, TypeScript, Tailwind CSS 3.4, Prisma 5 with PostgreSQL."
04 Understand before copy-pasting Before inserting code: "Explain this code to me in plain language. What does each section do?"
05 Never skip security After every major feature: "Do a security review. Check for XSS, SQL injection, insecure auth, and exposed secrets."
06 Commit like a pro After every working step: commit. Use Conventional Commits: feat: add user authentication or fix: resolve cart count bug.
07 Define constraints Tell AI what it must NOT do: "No jQuery, no class components, no inline styles, no additional npm packages."
08 Read error messages Never send "it doesn't work." Always include the full error message, stack trace, and relevant code. Precise errors = faster fixes.
09 Don't skip testing At minimum, smoke tests for critical paths: login, checkout, core feature. Five tests that run in 30 seconds beat zero tests every time.
10 Document your decisions Keep an ARCHITECTURE.md with why key decisions were made. Six months from now, you'll be glad — and AI will give better suggestions.

Vibe on. Build things. Learn as you go.
From a senior developer who's been in your corner from the start.
